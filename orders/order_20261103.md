# 2026-11-03 指示記録

## 指示

ステータス表示を追加したMod版で、「Auto-Start Server」がONでも起動時に毎回 MCP Server Stopped になる。
ONのときは自動で Running になるよう、原因を調べて修正する。

## 原因

FreeCADは `InitGui.py` を、関数 `RunInitGuiPy` の中から globals を指定せずに `exec()` で実行する。
そのためトップレベルの名前は `exec` のローカルにしか入らず、同じファイルの関数の中からは見えない。

Mod版で追加した `_mcp_startup()` が中で `_auto_start_mcp()` を呼んでいたため、ステータス表示の設置後に
`NameError: name '_auto_start_mcp' is not defined` が発生し、サーバーが起動していなかった。
この例外は `try` の外で発生するため、`[MCP] Auto-start failed` の警告も出ない。

## 対応

- `addon/FreeCADMCP/InitGui.py`: ステータス表示の設置と自動起動を、それぞれ直接 `QTimer.singleShot` に渡すように変更
- `tests/test_initgui_startup.py`: FreeCADと同じ `exec` の実行方法で確認する回帰テストを追加
- `%APPDATA%\FreeCAD\v1-1\Mod\FreeCADMCP\InitGui.py` に修正版をコピー

## 確認結果

ユーザーデータを分離したFreeCAD 1.1.1を画面なし（offscreen）で起動し、ポートを19875に変更したコピーで確認した。

| 条件 | 結果 |
| --- | --- |
| 修正前・自動起動ON | Stopped（ログに `NameError`） |
| 修正後・自動起動ON | Running（`[MCP] Auto-start: RPC Server started`） |
| 修正後・自動起動OFF | Stopped（従来どおり） |

- テスト: `uv run --group dev pytest` で43件成功。新しいテストは修正前のコードで `NameError` になることを確認
- 未確認: 実環境のFreeCADの再起動後の表示（FreeCADが起動中だったため、利用者側で確認する）
- コミットは未実施（mainブランチ上の未コミットのMod改修と一緒に、利用者の判断を待つ）
